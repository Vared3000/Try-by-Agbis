Пользователь явно выбрал **полную миграцию всей `global.css`** (была
2382 строки), а не частичную и не отказ от неё. Уже перенесены в
колокейтед `*.module.css` (camelCase имена классов, тот же паттерн, что

  (`ClientEditModal` — не потребовалось, там всё уже общее)

  `OrderItemControls`, `ItemStatusActions`
  (`OrderMetaEditor` — не потребовалось, там всё уже общее)
- `ProductionPage`

**Осталось перенести:**

- `client/src/pages/NomenclaturePage.jsx` +
  `client/src/features/nomenclature/DefectGroupsPanel.jsx`
- `client/src/pages/CatalogPage.jsx`
- `client/src/pages/PriceListsPage.jsx`
- `client/src/pages/TransfersPage.jsx` +
  `client/src/features/transfers/OrderItemPickerModal.jsx`
- `client/src/features/orders/NomenclatureCombobox.jsx` +
  `client/src/features/orders/ServiceCombobox.jsx` — используют
  идентичный набор классов (`nomenclature-combobox`, `combobox-dropdown`,
  `combobox-hint`, `combobox-input-wrap`, `combobox-results-count`) в
  обоих файлах. Это законный случай общего модуля — можно either (а)
  оставить в global.css как есть (это UI-примитив уровня
  design-system, как кнопки), либо (b) создать один
  `Combobox.module.css`, который импортируют оба файла. Оба варианта
  нормальны, решай на месте.

**Что оставить в `global.css` навсегда** (проверено breadth-грепом,
используется в 3+ несвязанных местах — это не забытые файлы, а
осознанно общий слой): сброс/типографика, кнопки
(`primary-button`/`secondary-button`/`text-button`/`danger-button`),
базовые стили формы + `form-error`/`field-error`, весь модальный
"скелет" (`modal-backdrop`/`modal-card`/`modal-head`/`modal-close`/
`modal-form`/`modal-actions`), `status-pill` + все варианты
`status-*` (используются в заказах/производстве/перемещениях
одновременно), `avatar`, `empty-state`, `panel`/`panel-title`/`stack`/
`eyebrow`, `table-toolbar`/`table-actions`/`module-toolbar`,

### Как делать (тот же процесс, что уже отработан в этой сессии)

1. Для каждого файла: `grep` каждого className по всему `client/src`
   **перед** удалением из `global.css` — не полагайся на то, что классы
   в одном комбинированном селекторе (`.a, .b, .c { ... }`) обязательно
   принадлежат одному файлу. **Это конкретная ошибка, которую я сделал
   в этой сессии** (удалил `.order-summary` и `.online-badge` из
   global.css, не проверив, что `ProductionPage.jsx` тоже их использует
   — нашёл только финальной сверкой в конце). Если что-то используется
   в 2+ несвязанных файлах — либо оставь в global.css, либо дай каждому
   файлу свою копию под своим именем, но не удаляй общее правило,
   не проверив всех потребителей.
2. Bare-строковые модификаторы состояния (`active`, `danger`,
   `overdue`, `completed`, `in_progress`, `rework`, `current` и т.п.) —
   применяются в JSX как обычные строки (`className={x ? 'active' : ''}`),
   не через `styles.x`. При переносе родительского класса в модуль такие
   модификаторы нужно оборачивать в `:global(...)`, иначе стилизация
   тихо перестанет работать (CSS Modules скоупит вообще все селекторы
   в файле по умолчанию). Примеры уже есть в каждом
   `*.module.css`, который создан в этой сессии — смотри на них как на
   образец синтаксиса.
3. После каждого файла/группы файлов: `pnpm lint` и
   `pnpm --recursive test` — оба должны быть зелёными.
4. Визуальная проверка вживую: временный `.mjs`-скрипт на Playwright
   **из корня репозитория** (не из scratch-директории — иначе не
   найдёт `node_modules`). Логин `owner@example.invalid` /
   `DevPass123!`. Навигация — кликами по сайдбару, не `page.goto()` на
   внутренний роут (токен только в памяти, полная перезагрузка его
   сбрасывает). Скриншот, прочитать инструментом чтения, убедиться, что
   макет не съехал. Удалить скрипт и скриншоты после проверки.
5. Коммит после каждого законченного файла/логической группы — не
   копить в один гигантский коммит.
6. **В самом конце**, после переноса всех оставшихся файлов, ОБЯЗАТЕЛЬНО
   повтори полную сверку по всему репозиторию (это заняло одну команду
   и поймало 2 реальных бага в этой сессии):

   ```bash
   grep -rohE 'className=("[a-zA-Z][a-zA-Z0-9_ -]*"|\{`[^`]*`\})' client/src --include="*.jsx" \
     | grep -oE '[a-zA-Z][a-zA-Z0-9-]*' | sort -u > /tmp/all_classes_used.txt
   while read -r cls; do
     grep -q "\.$cls[^a-zA-Z0-9_-]" client/src/styles/global.css 2>/dev/null \
       || grep -rq "\.$cls[^a-zA-Z0-9_-]" client/src --include="*.module.css" 2>/dev/null \
       || echo "MISSING: $cls"
   done < /tmp/all_classes_used.txt
   ```

   В выводе будет шум (JS-переменные вроде `className`, `document`,
   `styles`, фрагменты динамических строк вроде `status-`/`urgent`) —
   это нормально, игнорируй. Реальная проблема — если там всплывёт
   класс, который явно должен быть стилизован (сравни с тем, что было
   в `git show <любой коммит до начала сессии>:client/src/styles/global.css`,
   если сомневаешься, существовал ли класс раньше).
