# Отчёт по итерации 6 — заказы

## Реализовано

- tenant- и branch-scoped список и карточка заказов;
- создание черновика с проверкой клиента, филиала и точки приёма;
- атомарная последовательность номера в области точки приёма и бизнес-даты;
- неизменяемый отображаемый номер с контрольной цифрой;
- несколько изделий в заказе;
- глобально уникальный непрозрачный `scanCode` без персональных данных;
- назначение нескольких услуг изделию;
- поиск действующего прайс-листа и цены по типу изделия;
- snapshot названия услуги, ставки, количества и итоговой цены;
- целочисленный серверный расчёт денег с округлением;
- агрегирование стоимости изделия и заказа в транзакции;
- оформление только полного заказа, где у каждого изделия есть услуга;
- история перехода `draft → accepted`;
- обязательный `Idempotency-Key` при оформлении и повтор исходного ответа;
- контролируемая отмена черновика или принятого заказа;
- HTML-квитанция;
- данные этикетки для QR и Code 128 через защищённый API;
- серверный рендер QR и Code 128 в SVG и PNG;
- QR использует коррекцию ошибок H и quiet zone 4 модуля для печатных бирок;
- печатный SVG-шаблон 55×55 мм объединяет номер заказа, QR 36×36 мм и
  Code 128 шириной 48 мм;
- `LocalFileStorage` за сменяемым интерфейсом;
- загрузка фотографий JPEG/PNG/WebP до настраиваемого лимита;
- проверка MIME и magic bytes, SHA-256 checksum и безопасное имя хранения;
- защищённая выдача фотографий с tenant/branch scope и `nosniff`;
- отдельный Docker volume для загруженных файлов.

## Проверки

- PostgreSQL integration-тест полного сценария:
  черновик → изделие → price snapshot → оформление;
- проверка итоговой цены и сохранённого названия услуги;
- проверка непрозрачного scan code;
- проверка HTML-квитанции и label API;
- проверка SVG QR, PNG Code 128, загрузки и точной выдачи байтов фотографии;
- существующие auth, RBAC и tenant isolation тесты.

## Дальнейшее расширение

- общий idempotency middleware для будущих финансовых операций.
