# Управление проектом

## Риски

| Риск                                      | Мера                                                       |
| ----------------------------------------- | ---------------------------------------------------------- |
| Утечка tenant-данных                      | обязательный tenant context и негативные integration-тесты |
| Двойная оплата/возврат/выдача             | idempotency, транзакции, row lock, unique constraints      |
| Ошибочная связь разных организаций        | tenant-scoped repositories и составные проверки связей     |
| Изменение старой цены                     | snapshot услуги и цены при оформлении                      |
| Гонки номера заказа                       | отдельная атомарная последовательность точки               |
| Неоднозначный статус при частичной выдаче | отдельный `partially_issued` и агрегатор статуса           |
| Избыточная гибкость маршрутов             | data-driven маршруты при системных инвариантах в коде      |
| Несанкционированный доступ к фото         | авторизованная выдача и отсутствие PII в URL/коде          |
| Расхождение OpenAPI и реализации          | contract validation и integration-тесты                    |
| Рост границ MVP                           | изменения проходят отдельное согласование                  |

## Допущения

- локаль `ru-RU`, валюта `RUB`, часовой пояс `Europe/Moscow`;
- ручная скидка требует `discounts.manual` и причины;
- выдача с долгом запрещена без `orders.issue_with_debt`;
- разрешено перемещение готового изделия между филиалами с аудитом;
- до 10 фотографий на изделие по 10 МБ, JPEG/PNG/WebP;
- согласие хранит версию текста, дату, канал и принявшего сотрудника;
- уведомление MVP внутреннее;
- квитанция нефискальная и печатается из HTML;
- QR и Code 128 содержат один непрозрачный scan code;
- код точки приёма настраиваем и неизменяем после появления заказов.

## Критерии приёмки этапа 1

- определены назначение и границы MVP;
- зафиксированы стек и архитектура;
- перечислены модули и основные сущности;
- создана предварительная ER-диаграмма;
- описаны состояния заказа и изделия;
- частичная выдача отражена в данных, workflow и API;
- создана предварительная матрица RBAC;
- определены API-группы и критические ошибки;
- зафиксированы backlog, риски и допущения;
- все подтверждённые ответы заказчика внесены в документы.

## Definition of Done будущих итераций

- backend проверяет permission и tenant scope;
- вход и выход соответствуют OpenAPI;
- миграция применима к чистой БД;
- добавлены релевантные unit/integration/E2E тесты;
- lint, тесты и production build проходят;
- обработаны loading, empty и error states;
- критические действия присутствуют в аудите;
- в коде и логах нет секретов и персональных данных;
- README и техническая документация актуальны;
- результаты проверок приведены в отчёте итерации.
