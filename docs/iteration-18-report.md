## Что хорошо

- очередь заказов стала похожа на рабочую таблицу: номер, клиент, срок, сумма и
  статус считываются по одной горизонтали;
- просроченный срок заметен без открытия заказа;
- фильтры статусов доступны одним нажатием;
- приёмщик может создать черновик, добавить позицию, принять заказ и напечатать
  квитанцию с клавиатуры;
- редкие сведения по изделию скрыты до запроса, поэтому длинный заказ занимает
  меньше места;
- создание клиента начинается с поиска, что снижает риск дублей.

---

## Что можно улучшить

### Экран приёмки

1. **Сейчас неудобно:** добавление изделия всё ещё содержит много полей в одной
   форме.
   **Почему:** приёмщик сначала выбирает позицию, а затем вынужден просматривать
   все характеристики.
   **Как сделать лучше:** следующим этапом разделить сценарий на быстрый выбор
   позиции и компактную панель уточнений, зависящую от типа изделия.
   **Почему лучше:** основные заказы оформляются быстрее, а редкие параметры не
   перегружают рабочее место.

2. **Сейчас неудобно:** очередь загружает до 100 записей без серверной пагинации.
   **Почему:** на реальной базе история станет длинной.
   **Как сделать лучше:** добавить cursor-пагинацию и виртуализацию после
   стабилизации API.
   **Почему лучше:** скорость интерфейса не будет зависеть от количества заказов.

3. **Сейчас неудобно:** горячие клавиши видны только рядом с отдельными кнопками.
   **Почему:** новый сотрудник не знает полный набор команд.
   **Как сделать лучше:** добавить вызываемую клавишей `?` памятку.
   **Почему лучше:** обучение проходит внутри рабочего экрана.

### Окно клиента

1. **Сейчас неудобно:** без предварительного поиска можно было сразу создать
   карточку.
   **Почему:** один клиент мог появиться в базе несколько раз с разным написанием.
   **Как сделано:** создание разблокируется только после завершённого поиска по
   телефону или ФИО.
   **Почему лучше:** совпадения видны до сохранения новой карточки.

## Конкретные изменения

- создан отдельный компонент очереди `OrderListPanel`;
- создан отдельный компонент черновика `OrderCreatePanel`;
- метаданные заказа и вспомогательные элементы изделия вынесены из
  `OrdersPage`;
- добавлены фильтры по всем рабочим статусам;
- добавлена SLA-индикация просроченных заказов;
- добавлены клавиши `F2`, `F4`, `F8` и `Ctrl+Enter`;
- горячие клавиши отключены во время ввода в поля и при открытом модальном окне;
- клиент создаётся только через поиск с ожиданием результата;
- фотографии изделий загружаются лениво;
- добавлены компонентные тесты очереди и горячих клавиш.

---

## Пример реализации

Рабочий сценарий приёмщика:

1. `F2` открывает новый черновик.
2. Кнопка выбора клиента открывает поиск по ФИО или телефону.
3. После выбора клиента приёмщик создаёт черновик.
4. `F4` переводит фокус на номенклатуру.
5. После добавления изделий `Ctrl+Enter` принимает заказ.
6. `F8` открывает печатную квитанцию.
