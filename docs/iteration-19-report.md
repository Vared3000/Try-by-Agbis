## Что исправлено

- устранён конфликт первого номера заказа при переходе на новый рабочий день;
- дата рабочего дня включена в печатный номер заказа;
- уникальный индекс учитывает точку приёмки, дату и порядковый номер;
- добавлен регрессионный тест заказа с тем же порядковым номером в другой день;
- клик по клиенту открывает полноценную карточку;
- в карточке видны контакты, комментарий, сводка и вся история заказов;
- заказ из истории открывается одним нажатием;
- кнопка «Новый заказ этому клиенту» открывает приёмку с уже выбранным клиентом;
- история ограничена доступными пользователю филиалами.

---

## Почему новый сценарий быстрее

Приёмщику больше не нужно повторно искать клиента после просмотра истории. Он
выбирает клиента один раз, проверяет прошлые обращения и сразу создаёт следующий
заказ. Это сокращает сценарий повторного обращения и уменьшает риск выбрать
однофамильца.

## Проверка

- unit-тест уникальности номера для разных рабочих дней;
- PostgreSQL integration-тест повторного sequence в разные даты;
- integration-тест API истории заказов;
- компонентный тест карточки клиента;
- компонентный тест передачи клиента в новый заказ.
