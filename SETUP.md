# Запуск CleanFlow ERP на новом компьютере

Пошаговая инструкция для разворачивания проекта после `git clone` /
`git pull` на другой машине.

## 1. Предварительные требования

Установить перед началом:

- **Node.js 24.x** (см. `"engines"` в `package.json`: `>=24 <25`)
- **pnpm 11.x** (`>=11 <12`) — если его нет: `npm install -g pnpm@11`
- **PostgreSQL 18** — установлен и запущен как локальный сервис
  (Windows: служба `postgresql-x64-18`; Linux/macOS — обычный локальный
  инстанс). Docker не используется.
- **git**

Проверить версии:

```bash
node -v      # должно быть 24.x
pnpm -v      # должно быть 11.x
```

## 2. Клонирование и зависимости

```bash
git clone git@github.com:Vared3000/Try-by-Agbis.git
cd Try-by-Agbis
pnpm install
```

## 3. Файл `.env`

`.env` в git не хранится (см. `.gitignore`), его нужно создать на новой
машине заново. Два варианта:

**Вариант А (проще всего, если есть доступ к старому ПК):** скопировать
`.env` из корня старого проекта в корень нового репозитория напрямую
(флешка, личный облачный диск и т.п. — не через публичные каналы, там
хранится секрет для подписи токенов и пароль от локальной БД).

**Вариант Б (создать с нуля):**

```bash
cp .env.example .env
```

Затем открыть `.env` и обязательно поменять:

- `POSTGRES_PASSWORD` — свой пароль для локальной роли Postgres
- `DATABASE_URL` — тот же пароль внутри строки подключения
- `ACCESS_TOKEN_SECRET` — случайная строка ≥32 символов, например:

  ```bash
  node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  ```

Остальные значения из `.env.example` подходят для локальной разработки
без изменений.

## 4. Настройка PostgreSQL

Если роль и база ещё не созданы, создать их через `psql` (значения
должны совпадать с `.env`):

```sql
CREATE ROLE cleanflow WITH LOGIN PASSWORD 'ваш_пароль';
CREATE DATABASE cleanflow OWNER cleanflow;
```

Дальше применить миграции и наполнить демо-данными:

```bash
pnpm --filter @cleanflow/server db:migrate
pnpm --filter @cleanflow/server db:seed
```

Seed создаёт демонстрационный филиал, справочники, номенклатуру,
8 клиентов и 8 заказов. Повторный запуск безопасен — не создаёт дублей.

## 5. Пароль демо-пользователя

Демо-пользователь `owner@example.invalid` создаётся сидом без пароля
(статус `invited`). Задать пароль интерактивно:

```bash
pnpm --filter @cleanflow/server user:set-password owner@example.invalid
```

(Если `.env` скопирован с уже настроенной базой со старого ПК — этот
шаг и предыдущий не нужны, там уже всё есть.)

## 6. Проверка перед запуском

```bash
pnpm lint
pnpm test
```

Если сервер тестов ругается на подключение к БД — проверьте, что
Postgres запущен и `DATABASE_URL` в `.env` верный.

## 7. Запуск

Клиент и сервер одной командой (параллельно):

```bash
pnpm dev
```

Либо раздельно в двух терминалах:

```bash
pnpm dev:server   # http://localhost:3000
pnpm dev:client   # http://localhost:5173 (если порт занят — Vite сам возьмёт 5174/5175...)
```

Открыть в браузере адрес, который Vite выведет в консоли (обычно
`http://localhost:5173`), и войти:

- **Email:** `owner@example.invalid`
- **Пароль:** тот, что задан на шаге 5

## Частые проблемы

- **`ECONNREFUSED` / ошибки БД при старте сервера** — Postgres не
  запущен или `DATABASE_URL` не совпадает с реальными
  пользователем/паролем/БД.
- **`pnpm test` — часть серверных тестов "skipped"** — переменная
  `DATABASE_URL` не подхватилась (проверьте, что `.env` лежит в корне
  репозитория, рядом с `package.json`, а не внутри `server/`).
- **Порт 5173/3000 занят** — либо освободить порт, либо просто
  использовать тот, что Vite/сервер выведут в консоль при старте.
